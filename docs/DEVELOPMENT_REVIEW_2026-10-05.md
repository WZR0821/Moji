# Moji 阶段总结与开发维护方案

日期：2026-10-05。范围：当前本地 iOS、Android 源码。本轮是稳定性与体验维护，按用户要求提供 1.4.1 / 39 未签名 IPA。双端版本配置已同步，旧版本化发布包保留。

## 1. 当前阶段判断

Moji 已具备完整的个人效率应用主流程，现在应进入“稳定性收口 → 可复现交付 → 持续迭代”阶段。近期优先级是保护数据、验证后台行为、控制界面和性能回归，再增加新功能。

本轮开始时，工作区已有 9 月的 Android 修改和新增页面。本轮在这些修改上继续完善，没有撤销、覆盖归档或擅自提交这些已有成果。Git 中目前只有三个历史提交，因此不能据此编造更细的早期开发日程。

## 3. 本轮实际改动

### 数据与 BUG

- 两端先识别归档或旧快照，再按对应格式解析。归档损坏不再退回为空快照；拒绝无关 JSON、错误应用标识、未知版本、重复标识和无效记录时间。保留旧版合法快照读取能力。
- iOS 接受有／无小数秒的 ISO 日期，并迁移旧 Android 的 `completed` 为 `completedLog`。Android 在导出和整理时写规范枚举。
- Android 恢复保留全天、上午等非精确时间的零时长记录；精确时间记录仍要求结束晚于开始。导入无效记录时整份拒绝，不静默删掉再覆盖。
- 两端导出／恢复清除设备本地日历事件 ID，保留同步意图；原设备当前关联不因导出而被修改。
- Android 导出直接读取数据库已提交快照，不依赖界面订阅的初始空值；初始化和数据变更共用锁。数据库内容解码失败会报错，不再当成空数据继续覆盖。显式从有效备份恢复时，先将损坏的原始 JSON 另存为 `Moji-before-restore-corrupt.json`，再恢复，避免损坏数据库反过来阻止修复。
- 恢复前保存本机副本；Android 的 `filesDir/Moji-before-restore.mojibackup`、iOS 数据目录的 `before-restore.mojibackup` 均只保留最近一次恢复前状态。它们不是异地备份，卸载或更换沙盒后不能依靠它们找回数据。
- Android 自动备份先写临时副本并回读校验，再替换目标。写入失败会反馈，后台任务会重试。文件提供方不保证原子重命名；若替换阶段失败，已校验的 `Moji-pending-*.mojibackup` 会保留，可手动选取恢复。
- Android 自定义分类、三个快捷计划预设进入备份并恢复；恢复外观后立即更新主题，重新协调提醒与番茄通知。
- 清单勾选改为数据库最新状态上的串行修改，防止界面订阅延迟造成连续操作丢失。

### 界面与性能

- 保留黑白朱红水墨风格；Android 恢复前列出四类条目数量，空备份单独提醒，处理中禁用重复确认并显示进度；结果与错误使用独立弹窗，避免被全屏设置页遮挡。恢复说明支持滚动，弹窗使用当前纸墨背景。
- iOS 单文件导入先后台读取、校验并显示条目数量，再确认替换。文件夹恢复路径仍沿用既有交互，见后续任务。
- Android 导入、导出、数据解码／排序／编码离开主线程；读取失败和目标文件不可写不再显示假成功。Android 导入设置 32 MB 上限，超限明确提示而非持续分配内存。
- 连续编辑产生的外部自动备份合并为停止操作约 1.5 秒后的一次写入。Room 保存仍逐次执行；若 App 在延迟窗口内退出，外部备份可能落后，应在换机前手动导出。
- 备忘搜索和分组按数据、关键词缓存，避免其他界面状态变化时重复扫描；清单搜索避免构造整段拼接文本。
- iOS 加载时复用日期解码器，同一份完全相同的快照不重复解码。
- 底部导航增加“已选中”无障碍语义；备份保留天数改为显示实际设置。

以上是代码层面明确减少的工作量，并未完成真机启动、帧耗时和耗电基准，不承诺百分比提速。

### 发布维护

- `Scripts/release.sh` 在构建前拒绝有未提交修改或未跟踪源码的工作区，避免安装包与 `git archive HEAD` 不一致。
- 拒绝覆盖已有同版本产物；增加 Android 单元测试、Release 静态检查和来源文件（版本、提交、UTC 构建时间）。构建后再检查源码是否变化。
- 新增 `Scripts/verify.sh`，统一 Android 检查与 iOS 编译／指定模拟器测试。它不修改版本、不创建密钥、不生成正式发布包。

## 6. 架构维护建议

1. **先统一契约，再扩展共享代码。** `core/` 与 `Shared/` 当前是两套实际执行规则。先让两端使用同一组日期、重复、备份样本；再评估把纯规则迁入 KMP 的收益。原生 UI、权限、通知、Widget 继续由各平台负责。
2. **大数据优化靠测量。** Android 目前仍在 Room 的单条记录中保存完整 JSON，每次修改仍是 O(N) 的整理和编码。后台化改善界面响应，不会消除全部计算成本。只有基准证明瓶颈后，再拆成计划／记录／备忘等表，并设计可回滚的迁移。
3. **状态转换保持单一入口。** 完成、跳过、撤销、专注结算、删除关联记录都应集中处理后继事项、通知、小组件和统计。UI 负责表达操作，不再自行拼接数据结果。
4. **区分本地身份与可迁移内容。** 文件夹权限、日历 ID、通知授权、Widget 实例配置不跨安装复用。备份字段新增要有默认值和旧版样本，不随意提高 schema 或删字段。
5. **错误要可恢复。** 本轮没有把两端快照和设置存储改成一个跨存储事务。进程恰好在恢复中途被杀、iOS 所有持久副本同时损坏、磁盘写满等仍需故障注入及恢复日志方案。

## 7. 每次修改与发布的维护流程

- 开发：记录具体复现步骤 → 加针对性回归 → 小范围修复 → 两端检查；不以测试数量替代关键场景覆盖。
- 合入前：运行 `Scripts/verify.sh`；涉及日期、统计、备份时运行双端相同样本；涉及 UI 时保存代表截图。
- 发布前：审查并提交当前所有应交付源码；提升 `version.properties` 并同步 Xcode 版本；确认真机关键场景；从干净提交执行 `Scripts/release.sh`。
- 发布档案：版本、提交、APK／AAB／IPA／源码、来源文件、哈希、测试日志、已知问题、一份旧版备份样本。签名密钥单独离线保存，不进源码或日志。
- 修复回归：保留旧包和原始备份。数据格式升级以后，不能仅安装旧包就假定能回退；先验证旧版本能否读取新数据。
