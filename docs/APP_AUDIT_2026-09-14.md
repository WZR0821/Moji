# Moji Android / iOS 审查报告

审查日期：2026-09-14。对象：本地最新源码、已有 1.4.0（38）发布产物。本次只检查，不修复业务代码、不重新发布。

## 结论

当前不能认定为“两端 UI、操作和数据完全一致”，也不建议直接按跨端数据兼容已完成的状态发布。最优先的问题是备份恢复：存在将无效文件接受为空快照的路径，Android 与 iOS 之间还有日期和枚举格式冲突，以及合法记录被过滤的问题。Android 的次级页面、设置、小组件和计时状态逻辑尚未完全对齐 iOS。

下文将“实际运行/模型探针确认”和“代码确认、尚未端到端复现”分开。P1 表示优先修复的数据安全或兼容问题，P2 表示影响正常操作/界面的缺陷，P3 表示维护与交付问题。优先级不代表已经在用户设备上发生。

## 优先修复：数据安全与跨端兼容

### F01 · P1 · 两端会把无关 JSON 或损坏的归档降级为空快照

- 位置：[Kotlin 解码入口](/Users/raydon/Documents/倒计时打卡/core/src/commonMain/kotlin/com/raydon/moji/core/MojiPolicies.kt:22)、[iOS 导入入口](/Users/raydon/Documents/倒计时打卡/Shared/SharedPersistence.swift:381)、[iOS 快照解码](/Users/raydon/Documents/倒计时打卡/Shared/PlanModels.swift:1188)。
- 两端都是“先尝试归档，失败后尝试旧快照”；旧快照的字段均可缺省。`{"notMoji":true}` 因而被接受为零记录、零计划快照。归档内部某个记录解码失败后，同样可能进入这个回退路径。
- Kotlin 直接调用生产解码器已确认；Swift 使用生产 `PlanSnapshot` 模型的隔离探针也已确认接受无关 JSON。代码中的后续导入会替换当前数据，不是合并。Android 选中文件后立即导入，缺少恢复确认。
- 建议：先辨别归档/旧快照结构；归档解析失败不得当旧快照处理；校验 appIdentifier、必需键、版本和所有记录，再备份当前数据并事务性恢复。恢复前显示实际条目数量。

### F02 · P1 · Android 导出的日期和“记录已做”枚举不兼容 iOS

- 位置：[Android 归档时间](/Users/raydon/Documents/倒计时打卡/androidApp/src/main/kotlin/com/raydon/moji/android/platform/BackupService.kt:23)、[Android completed 写入](/Users/raydon/Documents/倒计时打卡/androidApp/src/main/kotlin/com/raydon/moji/android/MojiViewModel.kt:98)、[iOS 枚举](/Users/raydon/Documents/倒计时打卡/Shared/PlanModels.swift:195)、[iOS 日期解码](/Users/raydon/Documents/倒计时打卡/Shared/SharedPersistence.swift:557)。
- Android 用 `Instant.now().toString()` 输出通常带小数秒的 ISO 时间；iOS 仅使用 `.iso8601`。本机 Swift 探针确认 `2026-09-14T04:30:00.123Z` 被拒绝。
- Android“记录已做”保存 `kind="completed"`，iOS 只接受 `planned` / `completedLog`。生产 Swift 枚举探针确认拒绝 `completed`。
- 影响：常规 Android 备份就可能无法正确恢复至 iOS；结合 F01，会从“导入失败”升级为“空数据覆盖”。此项无需异常输入即可触发格式冲突。
- 建议：建立双端共用格式契约、迁移 `completed`，支持有/无小数秒日期，并用双方实际导出的归档做往返测试。

### F03 · P1 · iOS 合法的无精确时长记录在 Android 恢复时消失

- 位置：[Android normalize](/Users/raydon/Documents/倒计时打卡/androidApp/src/main/kotlin/com/raydon/moji/android/data/MojiRepository.kt:160)、[iOS normalize](/Users/raydon/Documents/倒计时打卡/Shared/PlanModels.swift:1199)、[iOS 记录已做保存](/Users/raydon/Documents/倒计时打卡/Moji/App/PlanStore.swift:413)。
- iOS 全天/时段记录允许 `startDate == endDate`；Swift 生产模型探针确认 normalize 后保留。Android 对所有记录无差别要求 `endDate > startDate`，直接过滤，没有告知用户丢了哪些记录。
- 建议：统一精确时间和非精确时间记录的验证规则；导入展示保留/拒绝数量，禁止静默丢弃合法数据。

### F04 · P1 · 备份携带设备本地日历 ID，Android 删除时可能误删本机其他事件

- 位置：[Android 原样导出快照](/Users/raydon/Documents/倒计时打卡/androidApp/src/main/kotlin/com/raydon/moji/android/platform/BackupService.kt:24)、[导入替换](/Users/raydon/Documents/倒计时打卡/androidApp/src/main/kotlin/com/raydon/moji/android/platform/BackupService.kt:31)、[删除计划](/Users/raydon/Documents/倒计时打卡/androidApp/src/main/kotlin/com/raydon/moji/android/MojiViewModel.kt:145)、[日历删除](/Users/raydon/Documents/倒计时打卡/androidApp/src/main/kotlin/com/raydon/moji/android/platform/MojiPlatform.kt:193)。
- `calendarEventIdentifier` 随快照导入导出。设备 A 的数字事件 ID 在设备 B 没有相同身份含义；B 若恰好有同 ID 事件，删除导入计划会直接调用系统日历删除该 ID。代码未校验事件属于 Moji 或属于当前计划。
- 状态：条件性代码风险；没有对用户日历做删除实验。
- 建议：跨安装恢复清空本地 ID，重建关联；删除前验证所属关系。iOS 明示“单向添加一次”，不删除系统事件，Android 语义也应明确对齐。

### F05 · P1 · 冷启动自动备份可能把未加载的空状态写入备份

- 位置：[仓库初值](/Users/raydon/Documents/倒计时打卡/androidApp/src/main/kotlin/com/raydon/moji/android/data/MojiRepository.kt:29)、[备份导出](/Users/raydon/Documents/倒计时打卡/androidApp/src/main/kotlin/com/raydon/moji/android/platform/BackupService.kt:20)、[Worker](/Users/raydon/Documents/倒计时打卡/androidApp/src/main/kotlin/com/raydon/moji/android/platform/BackupService.kt:63)。
- Room 快照异步加载，StateFlow 初始值是空快照。Worker 直接读 `.value`，没有等待数据库就绪，然后以 `wt` 重写 latest 和当日备份。冷启动调度时存在保存空值的竞态；普通修改后的备份也可能抢在 Flow 更新前导出上一版状态。
- 状态：代码路径确认，未使用真实备份目录注入时序故障。
- 建议：备份读取数据库的一致性快照，明确 loading/ready 状态，采用临时文件写入后替换，避免空初值冒充真实数据。

## 操作逻辑与代码缺陷

### F06 · P2 · 重复计划在“跳过”或专注完成后不生成下一次

- [Android skipPlan](/Users/raydon/Documents/倒计时打卡/androidApp/src/main/kotlin/com/raydon/moji/android/data/MojiRepository.kt:71) 只改状态，[recordFocus](/Users/raydon/Documents/倒计时打卡/androidApp/src/main/kotlin/com/raydon/moji/android/data/MojiRepository.kt:131) 也只改状态；只有手动 toggle 完成会调用 recurrence。
- iOS [跳过](/Users/raydon/Documents/倒计时打卡/Moji/App/PlanStore.swift:550) 会追加后继，专注通过统一完成引擎处理。
- 复现路径：创建每日计划，选择跳过，或关联番茄钟并自然完成；检查次日。Android 链条中断。
- 建议：统一完成、跳过、撤销的状态迁移入口，集中处理后继、记录、提醒和计时关联。

### F07 · P2 · 已删除/完成/关闭提醒的计划仍可能按旧时间通知

- [闹钟调度](/Users/raydon/Documents/倒计时打卡/androidApp/src/main/kotlin/com/raydon/moji/android/platform/MojiPlatform.kt:49)、[通知接收](/Users/raydon/Documents/倒计时打卡/androidApp/src/main/kotlin/com/raydon/moji/android/platform/MojiPlatform.kt:108)、[计划修改入口](/Users/raydon/Documents/倒计时打卡/androidApp/src/main/kotlin/com/raydon/moji/android/MojiViewModel.kt:142)。
- 没有计划闹钟取消入口；删除、完成、跳过、推迟不重新协调闹钟；关闭提醒或总开关仅保存设置。Receiver 不查询计划是否仍存在、是否完成、是否允许通知。BootReceiver 也直接读取可能未就绪的快照。
- 建议：按稳定 ID 统一取消/重排，在触发时复核状态，等待仓库就绪再恢复闹钟。

### F08 · P2 · 暂停专注后改关联计划，会把已投入时间计给另一个计划

- [linkPomodoro](/Users/raydon/Documents/倒计时打卡/androidApp/src/main/kotlin/com/raydon/moji/android/MojiViewModel.kt:264) 只阻止 running 状态；暂停后允许换计划，保留 `accumulatedSeconds`，同时重置剩余时间和标题/分类。
- 路径：A 专注数分钟→暂停→关联 B→继续并保存。A 已累积时间会随新状态归入 B。暂停后切换阶段则直接清零累积时间，也没有确认。
- 建议：暂停但已有投入时禁止换关联/阶段，或先确认保存/丢弃旧段，再初始化新状态。

### F09 · P2 · 后台过期的专注记录使用重新打开 App 的时间

- [finishCurrentPomodoro](/Users/raydon/Documents/倒计时打卡/androidApp/src/main/kotlin/com/raydon/moji/android/MojiViewModel.kt:441) 用 `Instant.now()` 作结束、反推开始，没有按已保存 target 结算；[广播接收器](/Users/raydon/Documents/倒计时打卡/androidApp/src/main/kotlin/com/raydon/moji/android/platform/MojiPlatform.kt:108) 只发通知。
- 条件：进程不运行时计时到期，过一段时间才重新打开。记录会整体平移到重开时刻，跨日时影响统计。手动结束也复用 autoStart 逻辑，可能继续进入下一阶段。
- 建议：区分自然到期和手动结束，用真实段起止/预定结束时间结算，保证幂等。真实设备后台场景仍需专项验证。

### F10 · P2 · 从日历编辑返回后，“今日计划”可能实际显示其他日期

- [主页筛选](/Users/raydon/Documents/倒计时打卡/androidApp/src/main/kotlin/com/raydon/moji/android/PlanScreen.kt:78)、[日历回调](/Users/raydon/Documents/倒计时打卡/androidApp/src/main/kotlin/com/raydon/moji/android/PlanScreen.kt:201)。

- 路径：日历选明天→打开新建→取消/保存→退出日历。主页内容和“今日”标签不一致。
- 建议：主页固定今日语义，日历选择保留在日历路由；若支持主页日期模式，应统一标题、添加日期和返回今天操作。

### F13 · P2 · 周/月统计的跨日归属和无预计时长语义不正确

- [回顾统计](/Users/raydon/Documents/倒计时打卡/androidApp/src/main/kotlin/com/raydon/moji/android/ReviewScreen.kt:74)、[每日统计](/Users/raydon/Documents/倒计时打卡/androidApp/src/main/kotlin/com/raydon/moji/android/ReviewScreen.kt:140)、[月计划投入](/Users/raydon/Documents/倒计时打卡/androidApp/src/main/kotlin/com/raydon/moji/android/ReviewSecondaryScreens.kt:128)。

### F14 · P2 · 清单备忘编辑按行号重用 ID，完成状态会错位

### F16 · P2 · 备份恢复会遗漏部分个性化设置
